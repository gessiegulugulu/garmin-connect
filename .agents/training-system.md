# Garmin 训练系统协议

## 固定文件

- `memory.md`：用户确认的目标、动作、场地和偏好。制定建议前必须读取。
- `TRAINING_PLAN.md`：唯一有效的未来七日计划，位于仓库根目录，供 GitHub 直接展示。
- `history/YYYY-MM/`：按事件发生月份归档分析与计划变更。

## 日期范围

- 使用用户本地时区 `Asia/Shanghai`，输出绝对日期。
- 周复盘：`今天 - 7 日` 至 `昨天`，只包含七个完整自然日。
- 周计划：`今天` 至 `今天 + 6 日`。
- 日复盘：昨天；日调整：今天。

## 月度归档

按内容写入以下路径；目录不存在时创建：

- 健康对话：`history/YYYY-MM/health-YYYY-MM-DD-HHMM.md`
- 周复盘：`history/YYYY-MM/weekly-review-YYYY-MM-DD.md`
- 日复盘：`history/YYYY-MM/daily-review-YYYY-MM-DD.md`

计划修改不写入 `history`。所有计划变更只追加到 `TRAINING_PLAN.md` 的“调整记录”。日复盘归档只保存训练、恢复和调整依据，不保存计划变更明细。

归档使用简洁 Markdown，包含查询日期范围、关键指标、判断、建议和数据缺口。只保存支持结论的摘要，不保存 OAuth token、邮箱、密码、用户 ID、设备 ID、完整原始 API 响应或不必要的个人信息。

## 活跃计划格式

`TRAINING_PLAN.md` 保持以下结构：

1. 标题与七日日期范围。
2. 本周重点及恢复注意事项。
3. 七行计划表：日期、场地、训练、具体内容、强度、状态。
4. 调整记录：时间、原因、改动摘要。

状态使用 `计划`、`完成`、`调整`、`休息`。训练内容必须具体到动作、组数或时长；不确定重量时使用主观强度 RPE，不虚构重量。正式训练按约 60 分钟设计且通常不超过 60 分钟；恢复日可明显短于 60 分钟，不为凑时长增加训练量。

## Garmin 数据原则

- 优先使用已配置的 Garmin MCP 只读工具。
- 只查询回答问题所需的数据，优先摘要接口。
- 活动识别可能错误；动作名称以 `memory.md` 和用户陈述为准。
- 缺失数据要明确说明，不把手表估算值当作医学诊断。

## 健康与训练边界

- 根据趋势而非单个数值判断恢复状态。
- 健康分析使用“可能、提示、与……一致”等表述，不作诊断。
- 出现胸痛、呼吸困难、昏厥、意识异常、单侧无力等警示症状时，优先建议及时就医。
- 计划以健康、体态、可持续性为目标，兼顾推、拉、下肢、核心、有氧和恢复。
